# Планировщик бригад: REST API

Методы `CrewScheduleController` с примерами запросов и ответов.
Краткая таблица методов и устройство сервиса: [developer-guide.ru.md](developer-guide.ru.md).
Swagger UI: http://localhost:8080/swagger-ui.html.

## Общие правила

- Все пути начинаются с `/crew-schedules`.
- Заголовок `X-Session-Id` выбирает версию графика пользователя. Без него (или пустой) — `default_session_id`.
  Сессия без версии получает копию версии по умолчанию (текущий месяц, без смен бригад).
- Изменения хранятся только в версии (в памяти), в БД ничего не пишется. Версия удаляется после 24 ч простоя.
- Тело запроса — JSON (`Content-Type: application/json`).
- Даты — `yyyy-MM-dd`, месяц — `yyyy-MM`, дата и время — `yyyy-MM-ddTHH:mm:ss`.
- Тип смены `type`: `DAY` или `NIGHT` (в БД — `PLR_SM.SM` `1` / `2`). Время смен — из `PLR_SM` (поле `shifts`
  в ответах), сейчас 08:00–20:00 и 20:00–08:00 следующего дня.
- Id линии `lineId` — код `KC` из `PLR_LC`, например `БерЦГС1`.
- Id смены бригады: `{date}-{type}-{lineId}`, например `2026-11-03-DAY-БерЦГС1`. В URL id нужно кодировать
  (`encodeURIComponent`): `/crew-schedules/crew-shifts/2026-11-03-DAY-%D0%91%D0%B5%D1%80%D0%A6%D0%93%D0%A11`.
- Id сотрудника — табельный номер (TABN), id бригады — BRID.

В примерах ниже: месяц ноябрь 2026, линия `БерЦГС1` (KRC `170610060000`) «Линия 1», бригады 1 и 2.
Для краткости id смен в URL показаны без кодирования.

### Ошибки

Код 400 (неверный запрос), 404 (не найдено), 409 (конфликт с графиком), тело — `ErrorInfo`:

```json
{
  "sessionId": "a1b2c3",
  "message": "Line Линия 1 already has crew Бригада 2 on 2026-11-03, DAY shift."
}
```

Если версии ещё нет вообще (не удалось загрузить данные при запуске), любой метод, кроме `GET /lines` и `POST /init`,
вернёт 404 с сообщением `No schedule version yet. Press New empty month.`

### Ответ `RotationResponse`

Большинство изменений возвращают весь график по линиям. В `lines` есть все активные линии, также без смен
(тогда `days` пустой). В `days` только дни, где есть хотя бы одна смена; `dayShift` / `nightShift` — `null`,
если в эту смену бригады нет.

```json
{
  "sessionId": "a1b2c3",
  "versionId": "6f1d0c5e-3a7b-4a59-9c1e-2b8f0e4d7a10",
  "month": "2026-11",
  "shifts": [
    { "type": "DAY", "start": "08:00:00", "end": "20:00:00", "sng": "446", "hours": 12.0 },
    { "type": "NIGHT", "start": "20:00:00", "end": "08:00:00", "sng": "60;61", "hours": 12.0 }
  ],
  "lines": [
    {
      "line": { "id": "БерЦГС1", "krc": "170610060000", "name": "Линия 1" },
      "days": [
        {
          "date": "2026-11-03",
          "dayShift": {
            "id": "2026-11-03-DAY-БерЦГС1",
            "date": "2026-11-03",
            "type": "DAY",
            "line": { "id": "БерЦГС1", "krc": "170610060000", "name": "Линия 1" },
            "crew": { "id": 1, "name": "Бригада 1", "staffCount": 3, "lineId": "БерЦГС1" },
            "pinned": false,
            "employeeIds": [1002, 1003, 2001],
            "absentEmployeeIds": [1001],
            "extraEmployeeIds": [2001],
            "unavailableEmployeeIds": [1004],
            "staffCount": 3,
            "hours": 12.0,
            "start": "2026-11-03T08:00:00",
            "end": "2026-11-03T20:00:00"
          },
          "nightShift": null
        }
      ]
    },
    {
      "line": { "id": "БерЦГС2", "krc": "170610070000", "name": "Линия 2" },
      "days": []
    }
  ],
  "warnings": [
    {
      "type": "CREW_REST",
      "crewShiftId": "2026-11-03-NIGHT-БерЦГС2",
      "previousCrewShiftId": "2026-11-03-DAY-БерЦГС1",
      "crewId": 1,
      "employeeId": null,
      "restHours": 0.0,
      "message": "Бригада Бригада 1: отдых 0 ч между сменами 2026-11-03 день (БерЦГС1) и 2026-11-03 ночь (БерЦГС2), нужно не меньше 12 ч."
    }
  ]
}
```

`warnings` — предупреждения правила отдыха, считаются заново для каждого ответа и нигде не хранятся; ничего не
запрещают. Между концом одной смены и началом следующей должно быть не меньше `app.schedule.min-rest-hours` часов
(по умолчанию 12, переменная окружения `APP_MIN_REST_HOURS`). Время смен — реальное, из `PLR_SM`.

| Поле | Значение |
| --- | --- |
| `type` | `CREW_REST` — у бригады (её смены на всех линиях), `EMPLOYEE_REST` — у сотрудника (смены, где он действительно работает: замены считаются, дни отсутствия — нет) |
| `crewShiftId` | Более поздняя смена |
| `previousCrewShiftId` | Смена перед ней |
| `crewId` | Бригада (`CREW_REST`) или бригада более поздней смены (`EMPLOYEE_REST`) |
| `employeeId` | Табельный номер; `null` у `CREW_REST` |
| `restHours` | Часы между концом предыдущей смены и началом поздней (может быть меньше 0, если смены пересекаются) |
| `message` | Текст для пользователя |

Если у пары смен уже есть предупреждение бригады, такие же предупреждения её сотрудников не добавляются.
Граница с предыдущим месяцем пока не проверяется.

При 12-часовых сменах предупреждение дают: день → ночь той же даты, ночь → день следующего утра.
День → день следующей даты (12 ч отдыха) — нет.

Поле `generation` есть только в ответах генератора (`POST /generate`, `POST /init?generate=true`), поле `cleared` —
только в ответе очистки (`POST /crew-shifts/clear`), см. ниже.

`shifts` — время смен версии из `PLR_SM` (`ShiftTime`): `start` / `end` — время начала и конца (`end` не позже
`start` — конец на следующий день), `sng` — коды `PLR_SM.SNG` как в таблице, `hours` — длина смены.
Фронтенд берёт отсюда время для привязки перетаскиваемой смены и для подписей.

Поля линии: `id` — `PLR_LC.KC`, `krc` — старый код `PLR_LC.KRC`, `name` — `PLR_PLINES.SNM` по `KRC` (или `KC`).
Поле бригады `lineId` — её линия (`PLR_BR.KC`, может быть `null`); бригаду можно поставить на любую линию.

Поля смены бригады (`CrewShift`):

| Поле | Значение |
| --- | --- |
| `employeeIds` | Кто работает в смене: члены бригады на эту дату без снятых, плюс замены, без отсутствующих |
| `absentEmployeeIds` | Члены бригады, снятые только с этой смены |
| `extraEmployeeIds` | Сотрудники других бригад, добавленные в эту смену (замены) |
| `unavailableEmployeeIds` | Члены бригады и замены, которые не работают из-за отсутствия (отпуск, больничный, ...) |
| `staffCount` | Сколько людей нужно в смене: `crew.staffCount` (PLR_BR.NTB). `null` — норма не задана (NTB пусто, 0 или меньше): у такой смены нет дефицита |
| `pinned` | Закреплённую смену нельзя перенести или удалить |
| `start`, `end`, `hours` | Начало, конец и длина смены по времени из `shifts` |

### Ответ `CrewDetails[]`

Список бригад (по номеру) с линиями, где бригада работает в этой версии, и сотрудниками (по `position` —
`PLR_TB.POS`, без позиции в конце, — затем по ФИО). `crew` сотрудника — бригада на начало месяца, переводы — в `crewChanges`.
Сотрудник попадает в список бригады из своего `crew`.

```json
[
  {
    "crew": { "id": 1, "name": "Бригада 1", "staffCount": 3, "lineId": "БерЦГС1" },
    "lines": [{ "id": "БерЦГС1", "krc": "170610060000", "name": "Линия 1" }],
    "employees": [
      {
        "id": 1001,
        "fullName": "Иванова Анна Петровна",
        "position": null,
        "crew": { "id": 1, "name": "Бригада 1", "staffCount": 3, "lineId": "БерЦГС1" },
        "crewChanges": [
          { "from": "2026-11-15", "crew": { "id": 2, "name": "Бригада 2", "staffCount": 3, "lineId": "БерЦГС1" } }
        ],
        "absences": [
          { "id": "0b6e2f9a-8c1d-4e57-a3f0-5d2c9b7e1a44", "type": "VACATION", "from": "2026-11-20", "to": "2026-11-30" }
        ]
      }
    ]
  }
]
```

### GET `/crew-schedules/lines` — линии

Линии, которые действуют в текущем месяце (период `PLR_LC.DTBEG`..`DTEND`). Работает без версии и без заголовка
(линии загружаются отдельно при запуске). Отсортированы по имени.

```json
[
  { "id": "БерЦГС1", "krc": "170610060000", "name": "Линия 1" },
  { "id": "БерЦГС2", "krc": "170610070000", "name": "Линия 2" }
]
```

### GET `/crew-schedules/export.xlsx?from=&to=&employeeIds=&lineId=` — график в Excel

```http
GET /crew-schedules/export.xlsx?from=2026-11-05&to=2026-11-15&employeeIds=1001,1002
X-Session-Id: a1b2c3
```

Файл `.xlsx` из версии вызывающего (в памяти, на диск и в БД ничего не пишется).

| Параметр | Значение |
| --- | --- |
| `from`, `to` | Период (yyyy-MM-dd), обе даты включительно; без них — 1-е и последнее число месяца версии |
| `employeeIds` | Табельные номера через запятую: только эти сотрудники. Пусто — весь график |
| `lineId` | Только эта линия и сотрудники, которые на ней работают в периоде. Во фронтенде не используется |

```http
HTTP/1.1 200
Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet
Content-Disposition: attachment; filename="crew-schedule-2026-11-05_2026-11-15.xlsx"; filename*=UTF-8''%D0%93%D1%80%D0%B0%D1%84%D0%B8%D0%BA_%D0%B1%D1%80%D0%B8%D0%B3%D0%B0%D0%B4_2026-11-05_2026-11-15.xlsx
```

Имя файла (в `filename*`, UTF-8, RFC 5987; `filename` — ASCII-имя для старых клиентов):

| Что | Имя | ASCII |
| --- | --- | --- |
| Весь месяц | `График_бригад_2026-11.xlsx` | `crew-schedule-2026-11.xlsx` |
| Период | `График_бригад_2026-11-05_2026-11-15.xlsx` | `crew-schedule-2026-11-05_2026-11-15.xlsx` |
| Одна линия | `График_бригад_2026-11_БерЦГС1.xlsx` | `crew-schedule-2026-11.xlsx` |
| Несколько сотрудников | `График_сотрудников_2026-11.xlsx` (или с периодом) | `employee-schedule-2026-11.xlsx` |
| Один сотрудник | `График_сотрудников_2026-11_1001.xlsx` | `employee-schedule-2026-11-1001.xlsx` |

При CORS заголовок `Content-Disposition` открыт фронтенду (`exposedHeaders`). Ссылкой `<a href>` файл не скачать:
нужен заголовок `X-Session-Id`, поэтому фронтенд скачивает через `fetch`.

Листы (столбцы дней — только дни периода, итоги — только за период). Заголовок «График бригад — Ноябрь 2026» или
«График бригад — с 05.11.2026 по 15.11.2026»; с `employeeIds` — «График сотрудников — …».

| Лист | Содержимое |
| --- | --- |
| «По линиям» | Нет, если указаны `employeeIds`. Две строки на линию («Д 08:00–20:00», «Н 20:00–08:00», время из `PLR_SM`), столбец на день («1 вс»), в клетке бригада. Пустое место — розовая заливка; людей меньше `staffCount` — янтарная заливка и примечание «5 из 6» (если `staffCount` не задан — нет). Последний столбец — смен в строке за период |
| «По сотрудникам» | Группы по бригаде (на начало месяца) с её линией; «№», «Таб. №», «ФИО», дни, «Д», «Н», «Смен», «Часов» (по реальному времени смен). Клетка: Д, Н, ДН, О (отсыпной после ночи), В, Б, ОТ, У, ПР; замена — примечание «замена: <бригада>, <линия>», снятие со смены — «снят со смены: Д, <линия>». С `employeeIds` — только они |
| «Смены» | Только с `employeeIds`: строка на каждую отработанную смену периода (таб. №, ФИО, дата, день недели, Д/Н, начало, конец, линия, бригада, часы, «замена» = «да», если в чужой бригаде) и на каждое отсутствие (Б / ОТ / У / ПР с его частью внутри периода), по времени; после сотрудника — строка «Итого …» со сменами и часами |
| «Нарушения» | Только если есть предупреждения об отдыхе по сменам периода (с `employeeIds` — свои предупреждения сотрудников и предупреждения бригады по сменам, где они работают в составе бригады): дата, смена, линия, бригада / сотрудник, часы отдыха, сообщение |

Печать: A4, альбомная ориентация, поля около 1 см, по центру. Листы с днями делятся на две страницы в ширину после
середины периода (день 15 месяца; период до 10 дней — одна страница); на каждой странице повторяются строки заголовка и
первые столбцы («Линия», «Смена» / «№», «Таб. №», «ФИО»). «По линиям» — в высоту одной страницы, «По сотрудникам» —
сколько нужно. Вверху справа — месяц или период, внизу «Стр. N из M». Пустое место помечено «—», дефицит — « !» после
бригады (видно и на чёрно-белом принтере). Закреплены заголовок и первые столбцы, выходные слегка затенены.

| Код | Когда |
| --- | --- |
| 400 | Дата не в месяце версии («Период … не в месяце графика …»); `to` раньше `from` («Дата «по» … раньше даты «с» …»); неверный формат даты или номера |
| 404 | Нет версии графика; нет такой линии; нет такого сотрудника |

## Версия

### POST `/crew-schedules/init?month=yyyy-MM&generate=false` — новая версия

Перечитывает данные из БД (линии месяца, время смен, бригады и сотрудников `PLR_TB` на месяц) и создаёт для
сессии новую версию на месяц без смен бригад. Без `month` — текущий месяц.
Заменяется только версия этой сессии.

```http
POST /crew-schedules/init?month=2026-12
X-Session-Id: a1b2c3
```

Ответ: [`RotationResponse`](#ответ-rotationresponse) с новым `versionId`, `month: "2026-12"` и пустыми `days`.

`generate=true` (по умолчанию `false`): после создания версии генератор заполняет график всех линий с нуля
(как `POST /generate` с пустым телом); в ответе есть `generation`. При запуске сервера и без `generate` версия
пустая.

Ошибка 400: `month must be yyyy-MM, got: 12.2026`.

## Смены бригад

### POST `/crew-schedules/crew-shifts` — поставить бригаду на смену

```http
POST /crew-schedules/crew-shifts
X-Session-Id: a1b2c3
Content-Type: application/json

{ "date": "2026-11-03", "type": "DAY", "lineId": "БерЦГС1", "crewId": 1 }
```

Ответ: [`RotationResponse`](#ответ-rotationresponse).

| Код | Когда |
| --- | --- |
| 400 | Нет `date`, `type`, `lineId` или `crewId`; дата не в месяце версии |
| 404 | Неизвестная линия или бригада |
| 409 | На этой смене линии уже есть бригада; бригада в это время работает на другой линии |

### PUT `/crew-schedules/crew-shifts/{id}` — перенести смену или поменять бригаду

Тело такое же, как у POST: новые дата, смена, линия и бригада. Id смены меняется, если меняются дата, смена или
линия. Снятые сотрудники и замены сохраняются только при переносе на другую линию в то же время с той же бригадой.

```http
PUT /crew-schedules/crew-shifts/2026-11-03-DAY-БерЦГС1
X-Session-Id: a1b2c3
Content-Type: application/json

{ "date": "2026-11-04", "type": "NIGHT", "lineId": "БерЦГС1", "crewId": 2 }
```

Ответ: [`RotationResponse`](#ответ-rotationresponse). Ошибки — как у POST, плюс 404 (нет такой смены) и
409 (смена закреплена).

### DELETE `/crew-schedules/crew-shifts/{id}` — удалить смену

```http
DELETE /crew-schedules/crew-shifts/2026-11-03-DAY-БерЦГС1
X-Session-Id: a1b2c3
```

Ответ: [`RotationResponse`](#ответ-rotationresponse). 404 — нет такой смены, 409 — смена закреплена.

### PUT `/crew-schedules/crew-shifts/{id}/pinned` — закрепить / открепить

```http
PUT /crew-schedules/crew-shifts/2026-11-03-DAY-БерЦГС1/pinned
X-Session-Id: a1b2c3
Content-Type: application/json

{ "pinned": true }
```

Ответ: [`RotationResponse`](#ответ-rotationresponse), у смены `"pinned": true`.

### POST `/crew-schedules/crew-shifts/pinned` — закрепить / открепить период

```http
POST /crew-schedules/crew-shifts/pinned
X-Session-Id: a1b2c3
Content-Type: application/json

{ "lineId": "БерЦГС1", "from": "2026-11-01", "to": "2026-11-10", "pinned": true }
```

`lineId: null` — все линии; `from: null` — 1-е число; `to: null` — конец месяца. Ответ:
[`RotationResponse`](#ответ-rotationresponse). 400 — дата не в месяце версии или `from` позже `to`; 404 — нет линии.

### POST `/crew-schedules/crew-shifts/clear` — очистить смены линии или всех линий за период

```http
POST /crew-schedules/crew-shifts/clear
X-Session-Id: a1b2c3
Content-Type: application/json

{ "lineId": "БерЦГС1", "from": "2026-11-05", "to": "2026-11-15", "includePinned": false }
```

Удаляет смены бригад линии в периоде `from`..`to` (обе даты включительно) вместе с изменениями людей этих смен
(снятые со смены и замены). `lineId: null` — все линии; `from: null` — 1-е число; `to: null` — конец месяца.
Закреплённые смены удаляются только при `includePinned: true`, иначе остаются. Смены вне периода не меняются.
Сколько смен в периоде (закреплённых и нет), заранее показывает
[`GET /generate/preview`](#get-crew-schedulesgeneratepreviewlineidfromto--что-есть-в-периоде).

Ответ: [`RotationResponse`](#ответ-rotationresponse) и `cleared`:

```json
"cleared": { "removed": 10, "keptPinned": 12 }
```

`removed` — сколько смен удалено, `keptPinned` — сколько закреплённых смен периода осталось.

| Код | Когда (ничего не меняется) |
| --- | --- |
| 400 | Дата не в месяце версии; `to` раньше `from` |
| 404 | Нет такой линии |

## Генератор графика бригад

### POST `/crew-schedules/generate` — заполнить график по циклу

Цикл бригады: **День → Ночь → Отсыпной → Выходной**. У каждой бригады цикла есть фаза (0..3): бригада работает днём
в каждую дату d, где `(d − фаза) mod 4 = 0` (d — номер дня от эпохи), и ночью на следующую дату. Дневная смена на x
даёт фазу `x mod 4`, ночная — `(x − 1) mod 4`. Каждая линия планируется отдельно, также при генерации всех линий.

```http
POST /crew-schedules/generate
X-Session-Id: a1b2c3
Content-Type: application/json

{ "lineId": "БерЦГС1", "from": "2026-11-10", "to": "2026-11-20", "startCrewId": null, "overwrite": false, "pin": true }
```

| Поле | Значение |
| --- | --- |
| `lineId` | Линия; `null` — все линии версии |
| `from` | Первая дата; `null` — 1-е число месяца версии. Должна быть в месяце версии |
| `to` | Последняя дата (включительно); `null` — последний день месяца версии. В месяце версии, не раньше `from`. Смены после `to` не меняются |
| `startCrewId` | Своя бригада линии, которая работает днём `from` в порядке по умолчанию. Только вместе с `lineId`. Опорные смены важнее: если они не позволяют, в `messages` будет сообщение |
| `overwrite` | `false` (по умолчанию) — незакреплённые смены остаются опорными, заполняются только пустые места; `true` — сначала удаляются незакреплённые смены генерируемых линий в периоде `from`..`to` |
| `pin` | `true` — созданные генератором смены закрепляются. По умолчанию `false` |

Источники фаз, по приоритету:

1. **Опорные смены** линии — смены, которые остаются: закреплённые; при `overwrite: false` также незакреплённые;
   смены до `from` и после `to` не удаляются, поэтому тоже опорные. Подходит любая бригада, также с другой линии. Для даты d
   берётся последняя опорная смена бригады не позже d, иначе самая ранняя после d.
2. Последняя неделя предыдущего месяца — пока не сделано (нет таблиц плана).
3. **По умолчанию**: свои бригады линии (`crew.lineId`) по номеру c0..c3, порядок дневных смен [c0, c2, c3, c1] с даты
   `from`.

Бригады цикла линии — бригады её опорных смен, дополненные до 4 своими бригадами (по номеру), которые не входят в цикл
другой линии этого запуска. Бригады без фазы занимают свободные фазы в порядке по умолчанию, повёрнутом так, чтобы
совпасть с опорными сменами.

Заполняются только пустые места периода `from`..`to`. Смены после `to` не меняются, даже если цепочка в них не
переходит: тогда в `messages` добавляется «Линия БерЦГС1: цикл не совпадает со сменами после 2026-11-20.» (проверяются
смены на `to + 1`: ночью должна работать дневная бригада `to`, днём — дневная бригада `to − 3`), а проблему покажут и
предупреждения об отдыхе (`warnings`). Если на место нет бригады, претендуют две или бригада занята, место остаётся пустым
и добавляется сообщение; остальное генерируется. Названия бригад не используются.

Ответ: [`RotationResponse`](#ответ-rotationresponse) и `generation`:

```json
"generation": {
  "created": 42,
  "kept": 1,
  "messages": [
    "Линия БерЦГС3: 3 бригады вместо 4, часть смен останется пустой.",
    "Линия БерЦГС3, 2026-11-03, дневная смена: нет бригады для этого места в цикле, смена оставлена пустой.",
    "Линия БерЦГС1, 2026-11-12, дневная смена: бригада Линия1/3 уже работает в это время на линии БерЦГС2, смена оставлена пустой."
  ]
}
```

`created` — сколько смен создано, `kept` — сколько мест уже было занято и осталось.

| Код | Когда |
| --- | --- |
| 400 | `from` или `to` не в месяце версии; `to` раньше `from` («Дата окончания … раньше даты начала …»); `startCrewId` без `lineId`; бригада не этой линии |
| 404 | Нет такой линии |

### GET `/crew-schedules/generate/preview?lineId=&from=&to=` — что есть в периоде

Считает места (линия, дата, смена) с `from` по `to` включительно. Ничего не меняет. Без `lineId` — все линии, без
`from` — с 1-го числа, без `to` — до конца месяца.

```json
{
  "from": "2026-11-29",
  "to": "2026-11-30",
  "lines": [
    { "lineId": "БерЦГС1", "lineName": "Линия 1", "pinned": 1, "unpinned": 0, "empty": 3 }
  ],
  "total": { "pinned": 1, "unpinned": 0, "empty": 3 }
}
```

400 — `from` или `to` не в месяце версии, `to` раньше `from`; 404 — нет линии.

### PUT `/crew-schedules/lines/{lineId}/sample` — очередь бригад линии

Дневные бригады 4 дней подряд (`from` .. `from + 3`). Удаляет незакреплённые смены линии (дневные и ночные) в эти дни
и ставит дневные смены очереди **закреплёнными**. График не генерирует: можно задать очереди нескольких линий и потом
заполнить все сразу. Ночные смены следуют из цепочки: ночью работает дневная бригада предыдущего дня.

```http
PUT /crew-schedules/lines/БерЦГС1/sample
X-Session-Id: a1b2c3
Content-Type: application/json

{ "from": "2026-11-01", "dayCrewIds": [14, 12, null, 13] }
```

`from: null` — 1-е число. В `dayCrewIds` ровно 4 элемента, минимум 3 разные бригады версии (любой линии). Ответ:
[`RotationResponse`](#ответ-rotationresponse).

| Код | Когда (ничего не меняется) |
| --- | --- |
| 400 | Не 4 элемента, меньше 3 бригад, повторы, 4 дня не помещаются в месяц |
| 404 | Нет линии или бригады |
| 409 | Дневная смена закреплена за другой бригадой; бригада в это время работает на другой линии |

## Люди одной смены

Эти изменения касаются только одной смены бригады; состав бригады не меняется.

### PUT `/crew-schedules/crew-shifts/{id}/employees/{employeeId}` — сотрудник работает в смене

Член бригады, снятый со смены, снова работает в ней; сотрудник другой бригады добавляется как замена.

```http
PUT /crew-schedules/crew-shifts/2026-11-03-DAY-БерЦГС1/employees/2001
X-Session-Id: a1b2c3
```

Ответ: [`RotationResponse`](#ответ-rotationresponse), `2001` в `employeeIds` и `extraEmployeeIds`.

| Код | Когда |
| --- | --- |
| 404 | Нет такой смены или сотрудника |
| 409 | Сотрудник отсутствует (отпуск, больничный, ...) в этот день; уже работает в этой смене; в это время работает на другой линии |

### DELETE `/crew-schedules/crew-shifts/{id}/employees/{employeeId}` — сотрудник не работает в смене

```http
DELETE /crew-schedules/crew-shifts/2026-11-03-DAY-БерЦГС1/employees/1001
X-Session-Id: a1b2c3
```

Ответ: [`RotationResponse`](#ответ-rotationresponse), `1001` в `absentEmployeeIds` (член бригады) или убран из
`extraEmployeeIds` (замена). 409 — сотрудник не работает в этой смене.

### POST `/crew-schedules/crew-shifts/{id}/replacements` — заменить сотрудника

Одним шагом: `employeeId` не работает в этой смене, `substituteId` работает вместо него.

```http
POST /crew-schedules/crew-shifts/2026-11-03-DAY-БерЦГС1/replacements
X-Session-Id: a1b2c3
Content-Type: application/json

{ "employeeId": 1001, "substituteId": 2001 }
```

Ответ: [`RotationResponse`](#ответ-rotationresponse).

| Код | Когда |
| --- | --- |
| 400 | Нет `employeeId` или `substituteId`; сотрудник заменяет сам себя |
| 404 | Нет такой смены или сотрудника |
| 409 | `employeeId` не работает в смене; `substituteId` отсутствует, уже работает в смене или в это время на другой линии |

## Сотрудники

### PUT `/crew-schedules/employees/{id}/crew` — перевести в другую бригаду

С даты `from` (в месяце версии) сотрудник в бригаде `crewId`; меняется состав обеих бригад во всех их сменах
с этой даты. Более поздние переводы сотрудника удаляются. Без `from` (или 1-го числа) — на весь месяц:
меняется `crew`, а не `crewChanges`.

```http
PUT /crew-schedules/employees/1001/crew
X-Session-Id: a1b2c3
Content-Type: application/json

{ "crewId": 2, "from": "2026-11-15" }
```

Ответ: [`CrewDetails[]`](#ответ-crewdetails), у сотрудника
`"crewChanges": [{ "from": "2026-11-15", "crew": { "id": 2, ... } }]`.

| Код | Когда |
| --- | --- |
| 400 | Нет `crewId`; дата не в месяце версии |
| 404 | Нет такого сотрудника или бригады |

### DELETE `/crew-schedules/employees/{id}/crew-changes/{from}` — отменить перевод

```http
DELETE /crew-schedules/employees/1001/crew-changes/2026-11-15
X-Session-Id: a1b2c3
```

Ответ: [`CrewDetails[]`](#ответ-crewdetails). 404 — у сотрудника нет перевода с этой даты
(`Иванова Анна Петровна has no crew change on 2026-11-15.`).

### POST `/crew-schedules/employees/{id}/absences` — добавить отсутствие

`type`: `VACATION` (отпуск), `SICK_LEAVE` (больничный), `DISMISSAL` (увольнение, без `to`), `OTHER`.
`from` и `to` включительно. Сотрудник не работает ни в одной смене, которая начинается в эти дни
(ночная смена — по дате начала). Id отсутствия создаёт сервер.

```http
POST /crew-schedules/employees/1001/absences
X-Session-Id: a1b2c3
Content-Type: application/json

{ "type": "VACATION", "from": "2026-11-20", "to": "2026-11-30" }
```

Увольнение:

```json
{ "type": "DISMISSAL", "from": "2026-11-25" }
```

Ответ: [`RotationResponse`](#ответ-rotationresponse), сотрудник в `unavailableEmployeeIds` смен в эти дни.
Новое отсутствие с его `id` видно в `GET /crew-schedules/crews` или `GET /crew-schedules`.

| Код | Когда |
| --- | --- |
| 400 | Нет `type` или `from`; нет `to` (кроме `DISMISSAL`); `from` позже `to`; период не пересекается с месяцем версии |
| 404 | Нет такого сотрудника |
| 409 | Пересекается с другим отсутствием сотрудника |

### DELETE `/crew-schedules/employees/{id}/absences/{absenceId}` — удалить отсутствие

```http
DELETE /crew-schedules/employees/1001/absences/0b6e2f9a-8c1d-4e57-a3f0-5d2c9b7e1a44
X-Session-Id: a1b2c3
```

Ответ: [`RotationResponse`](#ответ-rotationresponse). 404 — нет такого сотрудника или отсутствия.
